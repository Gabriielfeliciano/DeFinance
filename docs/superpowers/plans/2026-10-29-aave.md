# Posições na Aave v3 Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Show Aave v3 deposits, borrows and health factor per market for each EVM wallet, and make every total a net worth (wallet + supplied − borrowed).

**Architecture:** `/api/tokens` stays the only route. For EVM addresses the handler loads Aave in parallel with Alchemy through an injected `AaveSource` (Aave GraphQL API, no key). It removes the aTokens from `tokens`, adds `lending: LendingMarket[]`, and sets `lendingFailed: true` on any Aave failure, keeping today's behavior in that case. `totalValueUsd` keeps meaning "sum of `tokens`". The browser computes net values from the parts, because the chain filter and multi-wallet already compute there.

**Tech Stack:** Angular 22 standalone + Signals, Vercel Functions (Node 24), Aave GraphQL API `https://api.v3.aave.com/graphql`, Vitest 5.

**Spec:** `docs/superpowers/specs/2026-10-29-aave-design.md`

## Global Constraints

- Only Aave v3, only the EVM chains in `EVM_CHAINS`. Solana addresses never query Aave.
- All Aave v3 markets the API lists on those chains (Ethereum has four). No frozen/permissioned filter.
- Any failed Aave call for a wallet (markets, supplies, borrows, health factor) = Aave failure for that wallet: `lendingFailed: true`, `lending: []`, aTokens stay in `tokens` (today's behavior), `cache-control: no-store`.
- aTokens are removed from `tokens` by exact address from `markets.reserves.aToken.address`, never by name/symbol.
- Cache: no borrow in any market → today's `CACHE_CONTROL`; any borrow → `public, s-maxage=15` (no `stale-while-revalidate`); partial (chain or Aave failed) → `no-store`.
- Health factor: `null` when the market has no borrow (not shown); shown with two decimals in pt-BR (`1,38`); `> 100` above 100. Levels: `< 1.1` danger (red), `1.1 ≤ hf ≤ 1.5` warning (yellow), `> 1.5` safe (green).
- Net worth may be negative; never clamp to zero.
- UI copy (pt-BR, exact):
  - summary label with Aave: `Patrimônio líquido` (chain filter: `Patrimônio líquido em <Rede>`); without Aave, today's labels.
  - breakdown line: `Carteira US$ X · Aave depositado US$ Y · dívida −US$ Z` (values via `formatUsd`; minus sign `−` U+2212).
  - market card title: `Aave · <CHAIN_LABEL>`, extra markets `Aave · <CHAIN_LABEL> <Sufixo>` (e.g. `Aave · Ethereum Lido`).
  - card sections: `Depositado`, `Emprestado`; badge `Health factor 1,38`.
  - failure banner: `Não foi possível carregar as posições da Aave. O total pode estar incompleto.` with `Tentar novamente`.
- Old responses without `lending`/`lendingFailed` (CDN cache) = no Aave, as with `failedChains`.
- Never stage `package-lock.json`. Use explicit `git add <files>`.
- Commands: server/shared `npm run test:node`; front `npx ng test --watch=false` (one file: `--include <path>`); `npm run typecheck:server`; `npm run build`.
- Code style: English identifiers, short pt-BR doc comments, like the surrounding code.

## Review Focus

1. **Wallet with Aave positions and nothing priced in the wallet** → status `success` (not "vazia"), net shown. Test: Task 5 (`a wallet with only lending is success`).
2. **Health factor exactly 1.1 or 1.5** → `warning`. Test: Task 5 (`healthLevel` boundaries).
3. **Chain filter on a chain with only Aave positions** → chip exists, Aave card shown, total is that chain's net. Test: Task 6.
4. **Aave down, Alchemy up** → aTokens still listed, banner shown, response `no-store`. Tests: Task 4 and Task 6.
5. **Checksummed EVM address** (`0x970A…`) → Aave queried with the address form the API accepts (Task 1 Findings) and the same positions returned as for lowercase. Test: Task 4.

## Findings

Validado contra `https://api.v3.aave.com/graphql` em 2026-10-29 (carteira `0x970a…c425`). Fixture: `server/__fixtures__/aave.ts`. Gate: passou (aTokens existem e a USD vem em supplies/borrows).

1. **Queries.**
   - `markets(request: { chainIds: [..], user?: EvmAddress }) { name address chain { chainId name } reserves(request: { reserveType: BOTH, orderBy: { tokenName: ASC } }) { underlyingToken { address symbol name decimals imageUrl } aToken { address } vToken { address } } }`. `reserves` exige `request` com `reserveType` (SUPPLY|BORROW|BOTH) e `orderBy` com exatamente um campo (`tokenName`, `supplyApy` ou `borrowApy`). Ethereum core tem 67 reservas.
   - `userSupplies(request: { markets: [{ address, chainId }], user }) { market { name chain { chainId } } currency { symbol address } balance { amount { value } usd } isCollateral }`.
   - `userBorrows(request: { markets: [...], user }) { market { name chain { chainId } } currency { symbol address } debt { amount { value } usd } }`.
   - Valores numéricos são strings decimais (`BigDecimal`). Só retornam posições não vazias.
2. **Health factor: usar `markets(request: { chainIds, user }) { userState { healthFactor netWorth totalDebtBase totalCollateralBase } }`.** `Market.userState` não tem argumento, mas `MarketsRequest` aceita `user`: uma chamada cobre todos os mercados de todas as redes (testado com 21 redes). Sem `user`, `userState` vem `null`. Mercado sem posição: `healthFactor: null` e totais `"0"` (não `userState: null`). `userMarketState` por mercado não é necessário.
3. **Mercados e chainIds** (`chains { chainId name }` existe). Nomes dos mercados nas redes do DeFinance:
   - ethereum 1: AaveV3Ethereum, AaveV3EthereumEtherFi, AaveV3EthereumLido, AaveV3EthereumHorizon
   - arbitrum 42161: AaveV3Arbitrum; base 8453: AaveV3Base; optimism 10: AaveV3Optimism; polygon 137: AaveV3Polygon
   - bnb 56: AaveV3BNB (a Aave chama a rede de "BSC"); avalanche 43114: AaveV3Avalanche
   - zksync 324: AaveV3ZkSync; linea 59144: AaveV3Linea; scroll 534352: AaveV3Scroll; monad 143: AaveV3Monad
   - Sem mercado Aave (chainId só de referência, não verificado na Aave, que não os lista): berachain 80094, zora 7777777, unichain 130, shape 360, hyperevm 999, robinhood (chainId não verificável aqui).
   - Mercados em outras redes que o DeFinance não cobre: Gnosis, Sonic, Ink, Plasma, Mantle, MegaETH, X Layer, Celo, Metis, Soneium. Nota: vários mercados compartilham o mesmo endereço em redes distintas (0x794a…14aD em Arbitrum, Avalanche, Optimism, Polygon), então a chave de mercado é `(chainId, address)`.
4. **Endereço do usuário:** minúsculas e checksum funcionam; caixa mista com checksum errado também é aceita (checksum não validado); só o formato (tamanho/hex) é validado, erro `Failed to parse "EvmAddress": Invalid Ethereum address`. Endereços na resposta vêm em checksum, então comparar sempre em minúsculas.
5. **aToken x Alchemy:** Alchemy devolve `aEthWBTC` como `ethereum:0x5ee5bf7ae06d1be5997a1a72006fe6c607ec6de8`; `reserves.aToken.address` do WBTC em AaveV3Ethereum é `0x5Ee5bf7ae06D1Be5997A1A72006FE6C607eC6DE8`. Igual (case-insensitive). Observação: a Alchemy dá US$ 245.384 para o aToken, a Aave US$ 245.064 (preços de fontes distintas; usar o da Aave). Dívida (`variableDebt…`) não aparece na lista da Alchemy.
6. **Limites/erros:** nenhum header de rate limit (só Cloudflare: `cf-ray`, `cf-cache-status: DYNAMIC`). Erro de query vem com HTTP 200 e `content-type: application/graphql-response+json`: `{"data":null,"errors":[{"message":"Unknown field \"nope\" on type \"Market\".","locations":[{"line":1,"column":37}]}]}`. Portanto checar `errors` no corpo, não só `res.ok`. Erro de argumento também traz `data: null` (ou `data.markets: null` com `path`).
