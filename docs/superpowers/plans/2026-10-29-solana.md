# Carteiras Solana Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Accept a Solana address in the same wallet field, and show SOL plus SPL tokens summed into the multi-wallet portfolio.

**Architecture:** `solana` becomes one more `ChainId`, kept apart from the 17 EVM chains (`EVM_CHAINS`). `/api/tokens` detects the address kind: EVM queries the 17 EVM chains as today, Solana queries only `solana`, both through the same Alchemy Portfolio API client and mapper. Case handling moves to two small helpers (`addressKey` on the front, `contractKey` on the server), so nothing on Solana gets lowercased. The response shape (`TokensResponse`) does not change.

**Tech Stack:** Angular 22 standalone + Signals, Vercel Functions (Node 24), Alchemy Portfolio/Prices API, Vitest 5.

**Spec:** `docs/superpowers/specs/2026-10-29-solana-design.md`

## Global Constraints

- Max 3 wallets total, EVM and Solana mixed (`MAX_WALLETS = 3`, unchanged).
- Solana address: base58 (alphabet `123456789ABCDEFGHJKLMNPQRSTUVWXYZabcdefghijkmnopqrstuvwxyz`), 32–44 chars, decodes to exactly 32 bytes. No new dependency for base58.
- Nothing Solana is ever lowercased: wallet addresses, mints, `TokenItem.id` (`solana:<mint as Alchemy sent it>`), logo and price index keys. EVM keeps today's lowercase behavior.
- SOL native: symbol `SOL`, name `Solana`, 9 decimals. EVM natives stay 18.
- Spam/dust rules unchanged: no price, no metadata or below `MIN_VALUE_USD = 0.01` → dropped.
- Same timeout (15 s), CDN cache (`CACHE_CONTROL`, `no-store` on partial) and API-key redaction.
- UI copy (pt-BR, exact):
  - initial placeholder: `Endereço EVM (0x…) ou Solana`
  - invalid address: `Endereço inválido. Use um endereço EVM (0x…) ou Solana.`
  - chip label: `Solana`, last in the filter.
- Never stage `package-lock.json` (unrelated local change). Use explicit `git add <files>`.
- Commands: server/shared tests `npm run test:node`; front tests `npx ng test --watch=false` (one file: `--include <path>`); server types `npm run typecheck:server`; build `npm run build`.
- Code style: English identifiers, short pt-BR doc comments, like the surrounding code.

## Review Focus

1. **Hex string without `0x`** (`d8dA6BF26964aF9D7eEd9e93E53415D37aA9614f`, 40 chars, all base58-legal) → rejected, not taken as Solana. Test: Task 2 (`rejects ... hex without 0x`).
2. **Mint with uppercase letters** → `TokenItem.id` keeps the case and its CoinGecko logo and Prices API price are still found. Test: Task 3 (`keeps the mint case in id, logo and price lookups`).
3. **Two Solana addresses differing only in case** → treated as different wallets; the same EVM address in another case is still a duplicate. Tests: Task 2 (`addressKey`) and Task 6 (`wallet-input`).
4. **Solana wallet pasted with spaces around it** → trimmed and accepted, and the server gets it untouched otherwise. Test: Task 6 (`wallet-input`) and Task 4 (handler, `%20` around the address).
5. **EVM wallet request** → never calls `solana-mainnet`, and a Solana request never calls the 17 EVM networks. Test: Task 4.
